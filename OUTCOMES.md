## 1. What Was Built
- **Project**: a small Python command-line tool that converts temperatures between Celsius and Fahrenheit, with unit tests. It is a proof of concept meant to show that the tool is correct and that the AI-DLC workflow can take a small idea through to tested code.
- **Scope**: `poc` (initialization, intent capture, requirements analysis, code generation, build and test). Operation was skipped.
- **Units delivered**: a single unit with two files.
  - `temp_convert.py`: the converter (`c_to_f`, `f_to_c`, `format_result`, `parse_finite`, `main`).
  - `test_temp_convert.py`: 40 `pytest` cases covering FR1.1 to FR4.1.
- **Behaviour**:
  - `--c-to-f <n>` and `--f-to-c <n>` print the result rounded to 2 decimals and exit 0.
  - With no arguments it starts an interactive mode (`100 C`, `212F`; `q`, `Q`, an empty line or Ctrl-D quits).
  - `--help` prints usage with one example per direction.
  - Bad input (non-numeric, `nan`, `inf`, overflow, underscores, non-ASCII digits) writes a short message to standard error, prints nothing to standard output, and exits non-zero.
  - A result that rounds to zero prints `0.00`, never `-0.00`.
- **Key decisions**:
  - `main` takes its input and output streams as parameters and returns the exit code, so tests need no mocking.
  - `argparse` errors exit with code 2. Bad values and non-finite results exit with code 1.
  - Kelvin and other units are out of scope.
- **Tech stack**:
  - Tool: standard library only (`argparse`, `math`, `re`, `sys`), Python 3.9 or newer.
  - Tests: `pytest` (9.2.0 on CPython 3.14.8, 8.4.2 on CPython 3.9.6).
  - Tooling: `uv` with a project virtual environment.

## 3. Setup Guide
- **Prerequisites**: Python 3.9 or newer, and `uv` (only needed to run the tests).
- **Run the tool**: no installation. Use `python temp_convert.py --c-to-f 100`, `python temp_convert.py --f-to-c 212`, `python temp_convert.py` for interactive mode, or `python temp_convert.py --help`.
- **Environment variables**: none.
- **Run tests**:
  ```bash
  uv venv .venv
  uv pip install --python .venv/bin/python pytest
  .venv/bin/python -m pytest test_temp_convert.py -q
  ```
  Per the project rule, install Python tools only with `uv` into a virtual environment.

## 5. Architecture Decisions
| Decision | Alternatives considered | Why |
|---|---|---|
| One flag per direction (`--c-to-f`, `--f-to-c`) | Other CLI shapes offered at requirements | Clear syntax that is easy to test |
| No arguments starts interactive mode | One-shot only | Friendlier for other people who will run it |
| 2-decimal output, error exit on bad input | Other formats offered at requirements | Predictable output and scriptable failures |
| Standard library plus `pytest` | Third-party CLI or conversion libraries | No runtime dependencies (NFR1) |
| Streams passed into `main`, exit code returned | Patching `sys.stdin` and `sys.stdout` in tests | Tests need no mocking |
| Reject underscores and non-ASCII digits | Python's lenient `float()` parsing | Stricter, more predictable input, requested during review |

Constraints: Python 3.9 floor, standard library only for the tool, and the `uv` virtual environment rule for Python tooling.

## 8. Known Limitations and What to Tackle Next
- **Open questions**: none recorded.
- **Known limits**:
  - A negative value in exponent form must use `=`, for example `--c-to-f=-1e5`, because `argparse` reads a leading-dash value as another flag. Plain negatives such as `-40` work.
  - Only Python 3.9.6 and 3.14.8 were tested, not 3.10 to 3.13.
  - `.venv/` sits in the project root.
- **Deferred scope**: Kelvin and other units, and packaging or an installable command.
- **Suggested next steps**:
  - Commit the code and the intent record.
  - Run the suite on 3.10 to 3.13, for example in CI.
  - Decide whether to promote the poc to a packaged tool.
